# API Security Matrix

Per-endpoint security state on branch `cyber` (Phase 1 update). Status words: IMPLEMENTED / PARTIAL / NOT IMPLEMENTED / TESTED/PASSED / NOT TESTED / PLANNED / BLOCKED / DECISION REQUIRED.

Phase 1 changed the "Auth" column everywhere (dev header stub → verified Bearer JWT), added `GET /claims` and six insurer routes in `backend/src/endpoints/claimsInsurer.ts`, and added the tenant check to every `:claimId` route. Phase 0 counted 24 routes; the working tree now mounts **31 routes** in `src/index.ts` (15 GET, 14 POST, 2 PATCH across 7 routers: `gateway`, `policy`, `claims`, `claimsInsurer`, `ocr`, `identity`, `audit`).

**Global controls (all 31 routes):**

- **Bearer JWT required** (`requireActor`, `src/security/actor.ts`): `Authorization: Bearer <JWT>` verified with `hono/jwt` `verify` — HS256 pinned, `iss` = `JWT_ISSUER`, `aud` = `JWT_AUDIENCE`, `exp` and `iat` required, remaining lifetime ≤ 24 h (CUSTOMER) / 8 h (ASSESSOR, MANAGER, ADMIN), `tenant_id` required for insurer roles and forbidden for customers. Failure → 401 `{"error":"unauthenticated"}` with `WWW-Authenticate: Bearer realm="easyclaim"`; missing `JWT_SECRET` / `JWT_ISSUER` / `JWT_AUDIENCE` → 401 for every request (fail closed). The Phase 0 `X-Dev-Actor-*` stub is REMOVED. Revocation: NOT IMPLEMENTED (PLANNED). TESTED/PASSED in `auth.test.ts` (AUTH-001..014) and `actor.test.ts`; live ATTACK-P1-001..004d, 009, 010.
- No audit row is written for unauthenticated requests (no pre-auth database writes; AUTH-014).
- Request id generated server-side for every request (`src/index.ts`, `X-Request-Id` response header) and stored in `audit_events.request_id`; inbound request-id headers are ignored.
- Rate limit (same `RATE_LIMITER` binding, 100 req / 60 s per key, approximate): per IP (`cf-connecting-ip`) **before** authentication on `/api/*`, then per actor (`actor:<role>:<id>`) **after** authentication on `/api/v1/*`. TESTED/PASSED in `hardening.test.ts`; 429 observed live in Phase 0.
- 64 KB body limit.
- Security headers and CORS allowlist (`allowHeaders`: `Content-Type`, `Authorization` only).
- Generic 500 errors carrying only the request id.

**Object-level question** asked for each ID parameter: *"Does the server verify that this actor is allowed to access this specific object?"* Phase 1 update: for insurer roles the answer must include the **tenant check** — `loadAuthorizedClaim(c, claimId, mode)` in `src/security/claimAccess.ts` decides load → tenant → ownership → mode, where `isTenantInsurer()` = insurer role AND `actor.tenantId === claim.tenant_id` (non-null) AND `claim.stage !== 'Draft'`. Denied and missing both return 404 `{"error":"not_found"}` and write `authz.claim_access_denied` `{mode, exists, reason}` (reasons `missing`, `not_owner`, `cross_tenant`, `tenant_unset`, `draft`, `role`, `mode`; `transition_guard` from `transitionClaim`). Route order on every `:claimId` route: `requireActor` → coarse `requireRole` (resource-independent, so a 403 is not a cross-tenant existence oracle) → strict zod → `loadAuthorizedClaim` → `transitionClaim` → audit.
