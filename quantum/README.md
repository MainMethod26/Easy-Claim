# EasyClaim quantum track (Phase 4)

Experimental quantum-kernel one-class anomaly detection for the SCREENING stage, compared with a
classical one-class SVM on identical features. Simulator only. Advisory signal only.

```
quantum/
  easyclaim_quantum/
    features.py        5 features from existing claims columns (no invented business data)
    preprocessing.py   impute -> log1p -> min-max -> soft clip -> angles; shared by both models
    classical.py       OneClassSVM(rbf) baseline
    quantum_kernel.py  PennyLane feature map, fidelity kernel, kernel validation
    model.py           OneClassSVM(precomputed), percentile scores, bands, ScreeningSignal
    dataset.py         SYNTHETIC dev dataset generator (labelled), seed-claim loader
  experiment.py        runs everything, writes results/
  tests/               pytest (26 tests)
  data/dev_claims.json SYNTHETIC development data, committed for reproducibility
  results/             results.md, results.json, screening_signals.sql, demo_claims.sql
```

## Run

```bash
python -m venv quantum/.venv
quantum/.venv/Scripts/pip install -r quantum/requirements.txt     # POSIX: quantum/.venv/bin/pip
quantum/.venv/Scripts/python quantum/experiment.py                # add --regenerate to rebuild the dataset
npm run quantum:test   # runs pytest from quantum/ with the venv interpreter
```

Then, for the local Worker demo: `npm run signals:import:local && npm run demo:quantum:local`.

## Honesty notes

- All `dev_claim_*` rows are synthetic. Rows with `synthetic_anomaly: true` were generated by a named recipe; they are not fraud cases.
- Scores are percentiles against the synthetic reference population. By construction 20% of reference rows land at UNUSUAL or above and 5% at HIGH_ANOMALY.
- The quantum model did not outperform the classical baseline in the recorded run (see `results/results.md`). That is the measured result and is reported as such.
- Nothing here runs on quantum hardware. `execution` is `simulator` in every row.
